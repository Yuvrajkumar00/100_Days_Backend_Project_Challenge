## 🛠️ Project / Implementation
Implemented the refresh token flow in the Todo API.

### What I implemented
- Created refresh token controller
- Created refresh token route
- Verified refresh token using JWT
- Extracted `userId` and `sessionId` from the token
- Validated the session from MongoDB
- Checked session ownership
- Checked session revocation
- Checked session expiration
- Compared the hashed refresh token
- Generated a new access token
- Generated a new refresh token
- Implemented basic refresh token rotation
- Updated the session with the new refresh token hash
- Set the new refresh token in an HTTP-only cookie

## 🔐 Key Learning

### Access Token
Short-lived token used to access protected APIs.

### Refresh Token
Used to obtain a new access token when the access token expires.

### Session
Server-side record that controls whether a refresh token is still allowed to generate new access tokens.

### `revokedAt`
Used to manually revoke a session, such as during logout.

### `expiresAt`
Defines the maximum lifetime of a session.

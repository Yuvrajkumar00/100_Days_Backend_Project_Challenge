# Day 008 — User Logout & Session Revocation

## 📅 Date

26 September 2026

## 📚 Topic

User Logout with JWT Refresh Token & Session Revocation

## 🛠️ Project

Todo API — Authentication System

## ✅ What I Worked On

* Implemented the **user logout controller**.
* Retrieved the refresh token from the HTTP cookie.
* Handled the case where the refresh token is not present.
* Verified the refresh token using `jwt.verify()`.
* Learned that `jwt.verify()` **throws an error** when the token is invalid or expired.
* Used `try...catch` to handle invalid/expired refresh tokens.
* Extracted `sessionId` from the decoded refresh token.
* Found the corresponding session from the database.
* Revoked the session by:

  * Setting `refreshToken` to `null`
  * Setting `revokedAt` to the current date
* Cleared the refresh-token cookie after logout.
* Returned an appropriate logout response.

## 🔄 Logout Flow

```text
Logout Request
      ↓
Get refreshToken from Cookie
      ↓
RefreshToken exists?
   ↓          ↓
  No         Yes
  ↓           ↓
Clear       Verify JWT
Cookie         ↓
  ↓       ┌────┴────┐
Success   │         │
        Valid    Invalid/Expired
          ↓          ↓
      sessionId   Clear Cookie
          ↓          ↓
     Find Session  Success
          ↓
     Revoke Session
          ↓
     Clear Cookie
          ↓
     Logout Success
```

## 🧠 Key Learning

### `jwt.verify()` throws an error

An invalid or expired JWT does not simply return `false` or `null`.

```js
try {
    decoded = jwt.verify(
        refreshToken,
        config.REFRESH_TOKEN_SECRET
    );
} catch (error) {
    // Handle invalid or expired token
}
```

This was important for correctly handling logout when the refresh token has already expired.

## 🔐 Session Revocation

When a valid session is found:

```text
refreshToken → null
revokedAt    → current date
```

This prevents the session from being used for further refresh-token operations.

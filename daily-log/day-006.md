## 🛠️ Implementation

### 1. Verification Token Controller

* Created the verification token controller.
* Validated the verification token.
* Found the user using the hashed token.
* Checked token expiration.
* Marked the user as verified.
* Cleared the verification token after successful verification.

### 2. User Login Controller

Implemented the login flow:

```text
Email + Password
       ↓
Find User
       ↓
Compare Password
       ↓
Check Verification
       ↓
Generate Refresh Token
       ↓
Hash Refresh Token
       ↓
Create Session
       ↓
Set Refresh Token in HttpOnly Cookie
       ↓
Generate Access Token
       ↓
Send Response
```

### 3. Login Route

Created the login route and connected it with the login controller.

---

## 🔐 Authentication Flow

```text
User
 ↓
Login
 ↓
User Verification
 ↓
Password Check
 ↓
Create Session
 ↓
Refresh Token → Hash → Store in DB
 ↓
Refresh Token → HttpOnly Cookie
 ↓
Access Token → Client
```

---

## 🧠 Key Learning

Today I understood how **User, Session, Access Token, and Refresh Token** work together in an authentication system.

A session is created for each login, while the refresh token is stored securely as a hash in the database and the raw token is sent through an HttpOnly cookie.
